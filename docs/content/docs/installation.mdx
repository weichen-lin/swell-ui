title: Installation
description: Add swell-ui to a React 19 + Tailwind CSS v4 app.
---

Peer dependencies: `react` and `react-dom` 19, `tailwindcss` 4.3+. No icon package is needed: the
built-in icons are inline SVG, and each one can be swapped (see [Icons](/icons)).

```sh
pnpm add @weichenlin/swell-ui
```

In the CSS file that imports Tailwind:

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

`styles.css` brings the tokens (`theme.css`) and an `@source` that points Tailwind at the bundled
components, so their classes are generated even though Tailwind skips `node_modules` by default.

Then use the components. `toast()` needs one `<Toaster />` rendered near the root of your app:

```tsx
import { Button, toast, Toaster } from '@weichenlin/swell-ui'

export function App() {
  return (
    <>
      <Button onClick={() => toast.success('Saved')}>Save</Button>
      <Toaster />
    </>
  )
}
```

## Next.js App Router

The package entry starts with `'use client'`, so a Server Component can import and render the
components directly, with no wrapper file of your own:

```tsx
// app/page.tsx: a Server Component
import { Button } from '@weichenlin/swell-ui'

export default function Page() {
  return <Button>Deploy</Button>
}
```

Functions can't cross from a Server Component to a Client Component, so pass every function prop
from a Client Component: event handlers such as `onClick`, `Table`'s `getRowId` and column `cell`,
`Slider`'s `formatValue`, and the like. The non-component exports (`cn`, `toast`, `useTheme`) come
through the same client entry, so call them only from Client Components.
