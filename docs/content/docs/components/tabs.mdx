## Installation

```tsx
import { Tab, TabList, TabPanel, Tabs } from '@weichenlin/swell-ui'
```

The CSS comes with `styles.css`, imported once after Tailwind (see [Installation](/installation)):

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

## Usage

```tsx
import { Tab, TabList, TabPanel, Tabs } from '@weichenlin/swell-ui'

export function Example() {
  return (
    <Tabs defaultValue="a" aria-label="Sections">
      <TabList>
        <Tab value="a">A</Tab>
        <Tab value="b">B</Tab>
      </TabList>
      <TabPanel value="a">First</TabPanel>
      <TabPanel value="b">Second</TabPanel>
    </Tabs>
  )
}
```

A tablist needs a name: pass `aria-label` or `aria-labelledby`. Use `defaultValue` (uncontrolled) or `value` with `onValueChange` (controlled); one of the two is required.

## Accessibility

- `Tabs` follows the WAI-ARIA tabs pattern: `role="tablist"`, `tab` and `tabpanel`, linked by `aria-controls` and `aria-labelledby`. The types require a name for the tablist.
- Roving `tabindex`: Tab enters on the selected tab and arrow keys move within the list. The panel is a tab stop too, so Tab goes from the list straight into the content.
- Use `activationMode="manual"` when selecting a tab loads data, so arrowing past tabs does not fire requests.
- Disabled tabs are skipped by arrow keys and ignore clicks. A nested `Tabs` keeps its own list, keys and panels.
- The icon is `aria-hidden`. The bold label copy used to hold the width is hidden, so the name is read once; the badge is part of the name.
- `TabNav` is a `<nav>` with a list of real links: each can open in a new tab, and `aria-current="page"` marks where you are. Give it a name so it can be told apart from other navigation landmarks.
- On touch screens tabs are at least 44px, and the list is taller. In forced colors mode the indicator is `Highlight` and disabled tabs `GrayText`.
