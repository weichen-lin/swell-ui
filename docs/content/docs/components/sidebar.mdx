## Installation

```tsx
import {
  Sidebar,
  SidebarBody,
  SidebarGroup,
  SidebarHeader,
  SidebarItem,
  SidebarProvider,
  SidebarTrigger,
} from '@weichenlin/swell-ui'
```

The CSS comes with `styles.css`, imported once after Tailwind (see [Installation](/installation)):

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

## Usage

Wrap `Sidebar` and `SidebarTrigger` in a `SidebarProvider`, which shares the drawer's open state. From 960px up the sidebar is docked (240px wide, full height, sticky); below that it is hidden and `SidebarTrigger` opens the same content in a `Drawer`. The sidebar is `h-dvh` by default; pass a `className` such as `h-full` to size it to a container, as the demo does.

```tsx
import {
  Sidebar,
  SidebarBody,
  SidebarGroup,
  SidebarHeader,
  SidebarItem,
  SidebarProvider,
  SidebarTrigger,
} from '@weichenlin/swell-ui'

export function Layout({ children }: { children: React.ReactNode }) {
  return (
    <SidebarProvider>
      <div className="flex">
        <Sidebar aria-label="Primary">
          <SidebarHeader>Acme</SidebarHeader>
          <SidebarBody>
            <SidebarGroup label="Workspace">
              <SidebarItem href="/" aria-current="page">
                Overview
              </SidebarItem>
            </SidebarGroup>
          </SidebarBody>
        </Sidebar>
        <main>
          <SidebarTrigger />
          {children}
        </main>
      </div>
    </SidebarProvider>
  )
}
```

With a router, use `<SidebarItem asChild><Link href="/">Overview</Link></SidebarItem>`; the link sets `href` and `aria-current="page"`.

## API

### SidebarProvider

Holds the drawer open state. Takes `children` only.

### Sidebar

Also accepts `nav` props. Pass exactly one of `aria-label` or `aria-labelledby`; the types require it.

### SidebarTrigger

Menu button that opens the drawer; only shown below 960px. Also accepts `button` props except `children`, `type`, `aria-expanded` and `aria-controls`, which it sets.

### SidebarItem

Plain `a` props apply. Mark the current item with `aria-current="page"`. In the drawer, a click the link handles in place (`preventDefault`) closes the drawer; a modified click opens a new tab and leaves it open.

### Other parts

All take the standard props of their element.

| Part            | Description                                                            |
| --------------- | ---------------------------------------------------------------------- |
| `SidebarHeader` | Brand row pinned above the body; holds the close button in the drawer. |
| `SidebarBody`   | The groups; the only part that scrolls.                                |
| `SidebarFooter` | Pinned below the body.                                                 |
| `SidebarIcon`   | Decorative 16px leading icon for an item.                              |
| `SidebarBadge`  | Count at the end of an item, as a small `Badge`; takes `BadgeProps`.   |

## Accessibility

- The docked sidebar and the drawer both render a `nav` landmark that needs a name, so `aria-label` or `aria-labelledby` is required. The drawer is named the same.
- Only one copy of the content is in the DOM at a time: the drawer renders nothing while it is closed.
- Groups are lists, announced with their item count; a group `label` names the list.
- Items are links: set `aria-current="page"` on the current one. A router `Link` does this for you.
- `SidebarIcon` is `aria-hidden`. `SidebarBadge` is part of the item's name, with a space before it ("Projects 8").
- The drawer is modal: focus moves in, stays inside, and Esc, the close button (`Close navigation`) or a click on the backdrop closes it and returns focus to the trigger.
- Widening the window past 960px closes an open drawer.
- In forced colors mode the current item uses `Highlight` and `HighlightText`.
