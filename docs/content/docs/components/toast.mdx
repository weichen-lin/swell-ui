## Installation

```tsx
import { toast, Toaster } from '@weichenlin/swell-ui'
```

The CSS comes with `styles.css`, imported once after Tailwind (see [Installation](/installation)):

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

## Usage

Mount one `<Toaster />` near the root of your app, inside the router if an `action` renders a `<Link>`. Then call `toast` from anywhere: event handlers, mutations, loaders. Every call returns the toast's id.

```tsx
import { Toaster } from '@weichenlin/swell-ui'

export function App({ children }: { children: React.ReactNode }) {
  return (
    <>
      {children}
      <Toaster />
    </>
  )
}
```

```tsx
import { toast } from '@weichenlin/swell-ui'

toast({ title: 'Changes saved', description: 'Your settings are up to date.' })
toast.success('Synced')
```

## API

### toast

`toast(options)` shows a toast and returns its id. Calling it with the id of a toast still on screen replaces that toast in place; fields left out go back to their defaults.

```ts
toast(options: ToastOptions): string
```

### Helpers

```ts
toast.success(title: ReactNode, options?: Omit<ToastOptions, 'title' | 'type'>): string
toast.info(title: ReactNode, options?: Omit<ToastOptions, 'title' | 'type'>): string
toast.warning(title: ReactNode, options?: Omit<ToastOptions, 'title' | 'type'>): string
toast.error(title: ReactNode, options?: Omit<ToastOptions, 'title' | 'type'>): string
toast.loading(title: ReactNode, options?: Omit<ToastOptions, 'title' | 'type'>): string
toast.update(id: string, patch: ToastPatch): void
toast.dismiss(id?: string): void
toast.promise<T>(promise: Promise<T> | (() => Promise<T>), steps: ToastPromiseOptions<T>): string
```

| Function        | Description                                                                                     |
| --------------- | ----------------------------------------------------------------------------------------------- |
| `toast.success` | Success toast.                                                                                  |
| `toast.info`    | Info toast.                                                                                     |
| `toast.warning` | Warning toast.                                                                                  |
| `toast.error`   | Renders as the `danger` type; stays until dismissed.                                            |
| `toast.loading` | Spinner; stays until updated or dismissed.                                                      |
| `toast.update`  | Merges into a toast still on screen and restarts its timer. Does nothing for an unknown id.     |
| `toast.dismiss` | Plays the exit of one toast, or of all of them without an id.                                   |
| `toast.promise` | Loading toast that becomes success or danger in place when the promise settles. Returns the id. |

`ToastPatch` is `Partial<ToastOptions>` without `id` and `toasterId`: a toast stays in the Toaster it was created for.

### toast.promise

Takes a promise, or a function that returns one, and the steps for each outcome. A step is a title or full options without `id` and `type`; `success` and `error` can also be functions of the result or the error. Each step replaces the fields of the one before, so a loading description or action never lingers. If the user closes the toast before the promise settles, it stays closed.

## Accessibility

- Two live regions exist from the start, so announcements work: `role="status"` (polite) for most toasts and `role="alert"` (assertive) for `danger`. Toasts that arrive in the same frame are read together, and the same text announces again.
- A toast is announced when it appears. An update reads only its new state.
- Each card is labelled by its title and described by its description, and takes focus through F6 so its whole text is read.
- Hover, keyboard focus and a hidden tab pause the timers, so nothing expires while it is being read; the remaining time is kept, and only an update resets it. `danger` and `loading` never expire on their own.
- Icons are `aria-hidden`; the text carries the meaning. The loading spinner turns into a dashed ring under `prefers-reduced-motion: reduce`.
- With `dismissible: false` there is no close button, swipe or Esc: the toast leaves only by its timer or `toast.dismiss()`.
- Swipe goes toward the edge the stack sits on, plus the side for corner positions. Selecting text is not a swipe, and buttons and links keep their clicks.
- While a modal dialog is open, the stack moves into it, so toasts stay visible and reachable, and it moves back when the dialog closes.
- Up to 600px wide, cards fill the width with a 16px inset and at most 2 show at once.
- The viewport is labelled `Notifications (F6)` and the close button `Close`; both are English.
- In forced colors mode the card border is drawn in `CanvasText`.
- The server renders nothing: toasts exist only after a client call.
