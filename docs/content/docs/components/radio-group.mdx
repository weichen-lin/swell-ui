## Installation

```tsx
import { Radio, RadioGroup } from '@weichenlin/swell-ui'
```

The CSS comes with `styles.css`, imported once after Tailwind (see [Installation](/installation)):

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

## Usage

```tsx
import { Radio, RadioGroup, RadioGroupItems, RadioGroupLabel } from '@weichenlin/swell-ui'

export function Example() {
  return (
    <RadioGroup name="plan" defaultValue="pro">
      <RadioGroupLabel>Plan</RadioGroupLabel>
      <RadioGroupItems>
        <Radio value="free" label="Free" />
        <Radio value="pro" label="Pro" />
      </RadioGroupItems>
    </RadioGroup>
  )
}
```

`Radio` must be rendered inside `RadioGroup`. Nothing is selected until you pass `defaultValue` or `value`, or the user picks one.

## Anatomy

The group owns the wiring; you place each part, or leave it out.

```tsx
<RadioGroup name="plan" invalid={Boolean(error)}>
  <RadioGroupLabel>Plan</RadioGroupLabel>
  <RadioGroupDescription>Pick one.</RadioGroupDescription>
  <RadioGroupItems>
    <Radio value="free" label="Free" />
    <Radio value="pro" label="Pro" />
  </RadioGroupItems>
  {error && <RadioGroupError>{error}</RadioGroupError>}
</RadioGroup>
```

| Part                    | Role                                                                                                                 |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `RadioGroupLabel`       | Names the group. Appends the required asterisk.                                                                      |
| `RadioGroupDescription` | Muted hint, linked with `aria-describedby`.                                                                          |
| `RadioGroupItems`       | Default layout for the radios, following `orientation`. Any element works instead.                                   |
| `RadioGroupError`       | Group message, linked with `aria-describedby`. Takes `icon`; `false` or `null` hides it. Render it only when needed. |

### Hide the label

The label is a plain element, so style it freely. Add `sr-only` to keep it for assistive technology only:

```tsx
<RadioGroup name="plan">
  <RadioGroupLabel className="sr-only">Plan</RadioGroupLabel>
  <RadioGroupItems>{/* radios */}</RadioGroupItems>
</RadioGroup>
```

Without a label part, name the group with `aria-label` or `aria-labelledby` instead.

## Accessibility

- The group is a `<fieldset>` with `role="radiogroup"`, named by `RadioGroupLabel` through `aria-labelledby`, or by `aria-label` when there is no label part. Each radio is a native `<input type="radio">` named by its label.
- `RadioGroupDescription` and `RadioGroupError` are linked to the group, and also to each radio, with `aria-describedby`, only while they are rendered; the error icon is `aria-hidden`.
- `invalid` sets `aria-invalid` on the group, and `required` sets `aria-required`. Native validation needs one selection, with no custom submit handler.
- The selected value is submitted under the group `name`. Native form reset restores the uncontrolled default without calling `onValueChange`.
- `Radio` throws outside `RadioGroup`, and values must be unique and non-empty.
- On touch screens each row is at least 44px tall, so neighbouring hit areas do not overlap.
- In forced colors mode the radio uses `Canvas` and `Highlight`, and disabled uses `GrayText`.
