## Installation

```tsx
import { Tooltip } from '@weichenlin/swell-ui'
```

The CSS comes with `styles.css`, imported once after Tailwind (see [Installation](/installation)):

```css
@import 'tailwindcss';
@import '@weichenlin/swell-ui/styles.css';
```

## Usage

```tsx
import { Button, Tooltip } from '@weichenlin/swell-ui'

export function Example() {
  return (
    <Tooltip content="Pull the latest manifests from Git">
      <Button intent="secondary">Sync</Button>
    </Tooltip>
  )
}
```

[Button](/components/button) already wraps its own label (`aria-label` on an icon-only button) and `disabledReason` in a tooltip. Use `Tooltip` directly for any other trigger.

## Accessibility

- The bubble has `role="tooltip"` and the trigger points at it with `aria-describedby`, so the content is read as the trigger's description.
- Turn `describe` off when the tooltip only repeats the trigger's accessible name, such as an icon button's label.
- Keyboard users get the tooltip too: it opens on `:focus-visible` and closes on Esc.
- The bubble is not focusable, so keep buttons and links out of it.
- A trigger that is not interactive needs `tabIndex={0}` to be reachable.
- Events are read on the wrapper, so `aria-disabled` triggers still open it.
- With no `content`, nothing renders and no `aria-describedby` is added.
- The bubble is portaled to `<body>` with fixed positioning, so scroll containers such as tables and drawers never clip it. It follows scrolling and resizing.
- On the server only the trigger renders; the bubble appears after hydration.
- The transition is off under `prefers-reduced-motion: reduce`.
